## A1 — Specificity / enrichment terminology and metrics

### Findings

**Bug 1 — NSCLC lineage strip silently broken.**
`nsclc_kinase_expression.csv` on disk was generated by an uncommitted script version and has column `concentration`. The current `nsclc_expression.py` emits `specificity_score`. JS reads `r.specificity_score` → every tier badge renders as 0/empty. The data is correct; the column name is wrong.

**Bug 2 — `nsclc_kinase_specificity.csv` never loaded.**
This file has `n_detected_coarse` (# of 7 coarse TME groups where kinase is detected at ≥10%), `group_fraction`, `group_detected`, `concentration_coarse` per group. It directly answers A1's "how many of 7 cell types express at ≥10%". It exists on disk; it is not registered in `slices_audit.py` and not in the viewer payload.

**Missing feature — no CD4 / CD8 / Treg resolution in NSCLC strip.**
`nsclc_kinase_expression.csv` has 14 native ProjecTILs T-states with per-state `fraction_cells_expressing` and `mean_log2_expression`. The viewer collapses all T-states into a single `T_NK` bucket (`spec_group` field). Per-sublineage breakdown and sort do not exist anywhere in the viewer.

**Missing feature — "enrichment" label absent.**
Within-cohort ProjecTILs state concentration (`tcell_specificity`) is computed and in the payload, but is labeled "Share" in the verdict table. The term "enrichment" (concentration in a T-cell state) is used nowhere. There is no distinction between the two concepts in the UI.

### Gaps by deliverable

|---|---|---|
| # of NSCLC cell types expressing at ≥10% | `n_detected_coarse` exists in `nsclc_kinase_specificity.csv` but not loaded | Yes — needs loader + verdict column |

| Sort/filter by CD4, CD8, Treg | Not present | Yes — new UI control |

## A2 — Attribution: "vs bulk" → NES deconvoluted

### Findings

`tcell_concordance` (the "vs Bulk" column in the verdict table, `kinase_audit.js:614`) is `sign(bulk_NES) × tcell_lfc` — a direction product, not a deconvoluted NES. It has low discriminating power (acknowledged in `common.py:27–31`).

The projected-state MEA (`alz/cohorts/tcells/state_mea.py`) runs MEA on deconvoluted per-state substrate matrices (`ps_deconvoluted.csv`, `py_deconvoluted.csv`) and would produce a per-state NES × timepoint table. The viewer already has a loader (`_load_projected_state_mea_payload`, `slices_kinase.py:186`) and a bar chart (`kinase_audit.js:380–437`) wired for this output. Both are dead because the pipeline has never been run — `outputs/reports/kinase_attribution_tcells/donor1/state_mea/` does not exist.

### Gaps

| Item | Gap |
|---|---|
| `state_mea.py` never run | No outputs on disk; loader and chart exist but render empty |
| `decomposition_index` not built for T-cell | Chart reads `PAYLOAD.decomposition_index`; that key is AD-only; needs to be built from `projected_state_mea` output |
| "vs Bulk" label | Should be renamed once data is available |

### Files implicated

| File | Change needed |
|---|---|
| `alz/cohorts/tcells/state_mea.py` | Run to produce `donor1/state_mea/mea_projected_state.csv` |
| `alz/tcell_viewer/slices_kinase.py:186` | Wire `projected_state_mea` rows into a `decomposition_index`-compatible structure |
| `alz/tcell_viewer/template/js/tabs/kinase_audit.js:614` | Rename "vs Bulk" → "NES decomp" once data lands |

## A5 — Monotonic trend export script

### Findings

**Script exists and is complete.** `alz/cohorts/tcells/monotonic_export.py`

- Kinase side (donor1): reads `kinase_timepoint_nes{,_pY}.csv`, prepends NES=0 at d2, tests monotonicity across d2→d13→d15→d17→d19→d20. Outputs `monotonic_kinases.csv` (columns: donor, track, kinase, direction, n_timepoints, value per day, range, slope_ols).
- Substrate side (both donors): reads normalized phospho or stoichiometry matrices; weak/strict monotonicity with `--min-obs` NaN filter. Outputs `monotonic_substrates.csv`.

**Never run.** No `outputs/reports/kinase_attribution_tcells/monotonic/` directory exists. Not surfaced in viewer (standalone export only — that is appropriate per A5's "rarely used script" intent).
