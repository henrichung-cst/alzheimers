# Cell-Type Taxonomy Consolidation

Plan for collapsing the sprawling cell-label machinery so the cluster
mapping is cheap to change and runtime label assignment is no longer
duplicated.

Status: **proposal, not yet approved**.

---

## Guiding principle

**The nucleus → WMB class assignment is a curated artifact, not a
runtime derivation.**

One file, `nucleus_labels.csv`, is generated **once** by a deliberate
blessing step. Every downstream consumer joins against it by barcode.
Changing the gate (`subclass_prob ≥ 0.9`), the rollup source, or the
class taxonomy means re-running the blessing step with a new manifest
entry — a deliberate, auditable act. It never happens implicitly as a
side effect of editing config and re-running the pipeline.

This inverts today's design, where every consumer of the h5ad re-derives
labels at runtime with its own gate semantics (Path A gates on
`subclass_prob`, Path B doesn't).

---

## Current sprawl

Touch points anyone changing the taxonomy has to reason about today:

### Config (in `alz/config.py`)

| Symbol | Location | Role |
|---|---|---|
| `WMB_CLASSES` | `config.py:112-122` | Canonical 34-class list (prefixed) |
| `N_CELL_TYPES` | `config.py:137` | Derived count; wired into specificity thresholds |
| `CLASS_TO_TISSUE_CATEGORY` | `config.py:142-178` | 34-class → tissue rollup |
| `TISSUE_ORDER` | `config.py:183-188` | Tissue axis display order |
| `WMB_SUBCLASS_TO_CLASS_FILE` | `config.py:272` | Allen-shipped subclass→class CSV (338 rows) |
| `WMB_CLASS_MANIFEST_FILE` | `config.py:123` | 34-row class_name → class_label |
| `SEAAD_TO_WMB_CLASS_FILE` | `config.py:126` | SEA-AD subclass → WMB class |
| `SONG_MIN_SUBCLASS_PROB` | `config.py:290` | `0.9`; gate honored by Path A only |
| `load_song_to_wmb_class_map()` | `config.py:292-311` | Strip-prefix + read of subclass→class CSV |

### Code that assigns labels (the real choke point)

**Path A — Incytr export** (`alz/integration/export_factorial_inputs.py:537-572`):
- Reads `adata.obs["subclass_name"]` (338-vocab)
- Applies `subclass_prob ≥ 0.9` gate
- Maps subclass → class via `load_song_to_wmb_class_map()`
- Drops nuclei with unmapped subclass (count printed, no preservation)
- Writes `wmb_class` to `meta["labels"]`

**Path B — snRNA integration** (`alz/snrna_integration.py:61-115`):
- Reads `adata.obs["class_name"]` (34-vocab, already class-level)
- **No confidence gate**
- Maps `class_name → class_label` via `_build_class_name_to_label()`

Implicit consumers further downstream (`wmb_expression.py`,
`kinase_attribute.py`, `build_unified_viewer.py`) rely on the label
vocabulary matching `WMB_CLASSES` byte-for-byte but never re-derive it
themselves.

### What "changing the mapping" requires today

To bump `subclass_prob` from 0.9 to 0.8, the edit fans out to:

1. Edit `config.py:290`
2. Re-run `export_factorial_inputs.py` (Path A picks up the new gate)
3. **Path B is unaffected** — it never reads this constant. Silent divergence.
4. Re-run all downstream that depends on the factorial fixture

To collapse two WMB classes:

1. Edit `WMB_CLASSES`, `CLASS_TO_TISSUE_CATEGORY`
2. Possibly regenerate `wmb_subclass_to_class.csv` and `wmb_class_manifest.csv`
3. Re-run `wmb_expression.py`, Path A, Path B, attribution, viewer
4. Audit any hard-coded label strings in plot/viewer code (no central registry)

To swap the annotation provider (e.g. scANVI instead of Allen Cell Type
Mapper): touch every consumer that reads `subclass_name` / `class_name`
and rewrite each independently.

## Target architecture

Three pieces, three concerns:

### 1. The authoritative labels file (run once)

`outputs/reports/celltype_assignment/nucleus_labels.csv`:

| Column | Type | Notes |
|---|---|---|
| `barcode` | str | Primary key; matches `adata.obs_names` |
| `wmb_class` | str \| NA | Final 34-class label; NA when `status != "ok"` |
| `status` | str | `ok`, `low_confidence`, `unmapped_subclass` |
| `subclass_name` | str | Source Allen call (preserved for audit) |
| `subclass_prob` | float | Confidence at write time |

Plus `outputs/reports/celltype_assignment/MANIFEST.json` carrying full
provenance:

```json
{
  "generated_at": "2026-05-12T...",
  "alz_repo_git_sha": "<sha>",
  "source_h5ad": "data/datasets/song/primary/.../170_gex_celltypes_00.h5ad",
  "source_h5ad_sha256": "<sha256>",
  "gate": {"column": "subclass_prob", "min_value": 0.9},
  "rollup_source": "data/external/allen_abc/wmb_subclass_to_class.csv",
  "rollup_source_sha256": "<sha256>",
  "class_vocab_n": 34,
  "n_nuclei_total": 63000,
  "n_nuclei_assigned": 58000,
  "n_excluded_low_confidence": 4500,
  "n_excluded_unmapped": 500,
  "unmapped_subclasses": ["..."]
}
```

Generated by `alz/celltype_blessing.py` (new script). The cached output
is the canonical record. Re-running with a different gate, a new h5ad,
or a different rollup source produces a new manifest entry — and is a
deliberate operator action, never an automated pipeline behavior.

### 2. The taxonomy module (always available)

`alz/celltype_taxonomy.py` — thin, no h5ad reading at runtime:

```python
from alz.celltype_taxonomy import taxonomy

taxonomy.classes                  # ("01 IT-ET Glut", ..., "34 Immune")
taxonomy.n_classes                # 34
taxonomy.tissue_of("34 Immune")   # "Microglia"
taxonomy.class_to_tissue          # dict[str, str]
taxonomy.tissue_order             # tuple[str, ...]

labels = taxonomy.load_labels()   # pd.Series indexed by barcode → wmb_class
                                  # raises if MANIFEST sha256 ≠ current h5ad
```

The module owns:
- The 34-class vocabulary (single source of truth, mirrors `WMB_CLASSES`)
- The tissue rollup
- The labels-file loader (with a manifest-staleness check)

It does **not** own gate logic, subclass lookups, or live h5ad reading.
Those are confined to the blessing script.

### 3. The consumer pattern

Every consumer becomes a single join:

```python
from alz.celltype_taxonomy import taxonomy

labels = taxonomy.load_labels()
adata = adata[adata.obs_names.isin(labels.index)].copy()
adata.obs["wmb_class"] = labels.loc[adata.obs_names].values
```

No gate logic, no subclass lookup, no manifest read at runtime. Both
Path A and Path B reduce to this same snippet.

## What "changing the mapping" looks like after

| Change | Today | After |
|---|---|---|
| Bump `subclass_prob` threshold from 0.9 → 0.8 | Edit `config.py:290`; Path A picks up, Path B silently doesn't | Re-run `celltype_blessing.py --min-subclass-prob 0.8`; new `nucleus_labels.csv` + new manifest; both paths pick up |
| Collapse two WMB classes | Edit `WMB_CLASSES` + tissue rollup + possibly two external CSVs; audit literals everywhere | Edit `WMB_CLASSES` + tissue rollup; re-run blessing; re-run pipeline |
| Swap annotation provider (Allen Cell Type Mapper → scANVI) | Rewrite every consumer's label-derivation block | Rewrite `celltype_blessing.py` only |

The third row is the actual prize. "Labels come from the Allen Cell Type
Mapper" stops being a fact distributed across consumers and becomes a
fact owned by one script.

## Open question (must resolve before blessing)

Path A gates on `subclass_prob ≥ 0.9`; Path B doesn't. The blessing
step has to pick one value, and that decision will become the
gate for both paths.

1. **Bless at `0.9`** (Path A's current behavior). Path B loses some
   nuclei from `song_concordance.csv`. The number should be modest,
   but it shifts downstream confidence tiers slightly. Recommended:
   the gate exists for a reason and Path B not applying it looks like
   an oversight.
2. **Bless at a lower value (e.g. 0.5 or no gate).** Path A starts
   accepting low-confidence nuclei into the factorial fixture. Likely
   degrades path scoring.
3. **Bless at `0.9` and surface the diff as a one-time release note**
   before merging. Measure the Path B delta on a dry run first; if the
   drop is concentrated in classes with already-tight animal counts
   (`SONG_MIN_ANIMALS = 10`), reconsider.

Recommended: option 3 — measure before committing, then bless at 0.9.

## Migration steps

1. **Write `alz/celltype_blessing.py`.** Reads Song h5ad + Allen
   subclass→class CSV, applies gate, writes `nucleus_labels.csv` and
   `MANIFEST.json`. CLI args for `--min-subclass-prob`, `--source-h5ad`,
   `--rollup-source`, `--out-dir`. Idempotent: same inputs ⇒ same output.

2. **Dry-run measurement.** Run blessing at `subclass_prob ≥ 0.9` and
   compare Path B cohort sizes (per-class, per-animal) before vs. after.
   Decide on the final gate value here, before committing the blessed
   artifact.

3. **Run it once and commit.** Treat `nucleus_labels.csv` +
   `MANIFEST.json` as a checked-in curated artifact (same status as
   `wmb_kinase_expression.csv`).

4. **Write `alz/celltype_taxonomy.py`.** Vocabulary, tissue rollup,
   `load_labels()` with manifest sha256 check against the current
   h5ad. Re-export `WMB_CLASSES`, `CLASS_TO_TISSUE_CATEGORY`,
   `TISSUE_ORDER` so `from alz.config import WMB_CLASSES` keeps working
   via shim until consumers migrate.

5. **Migrate Path A** (`export_factorial_inputs.py:537-572`): replace
   the gate/rollup logic with `taxonomy.load_labels()` join. Assert the
   resulting cell set is byte-identical to the pre-migration output for
   the blessed gate value.

6. **Migrate Path B** (`snrna_integration.py:61-115`): same join. Record
   the cohort-count delta in the commit message and update any
   downstream that holds the pre-change counts (the unified attribution
   summary, viewer captions, etc.).

7. **Audit hard-coded class literals.** `grep` for both `"01 IT-ET Glut"`
   prefixed forms and bare `"IT-ET Glut"` forms; replace any consumer-
   side matches with `taxonomy.classes` references.

8. **Remove `load_song_to_wmb_class_map()`** from `config.py` once all
   callers have migrated. Allen CSV files stay on disk under
   `data/external/allen_abc/` (used by the blessing step).

9. **Wire prerequisite check.** `run_live_pipeline.sh` refuses to start
   if `nucleus_labels.csv` is missing or its manifest's
   `source_h5ad_sha256` doesn't match the h5ad on disk. Same gating
   pattern as `wmb_kinase_expression.csv`.

10. **Tests** (`tests/test_celltype_taxonomy.py`): 34-class invariant;
    `tissue_of` totality over `classes`; `load_labels()` raises on
    sha256 mismatch; blessing step is idempotent on a fixed fixture.

After step 8, "changing the cluster mapping" is one of:

- Edit `WMB_CLASSES` + `CLASS_TO_TISSUE_CATEGORY`, re-run blessing,
  re-run pipeline. *Two files, one re-run.*
- Edit the gate (`--min-subclass-prob`), re-run blessing, re-run
  pipeline. *Zero code edits.*
- Edit the blessing script to use a different annotation provider.
  *One file edit, downstream unchanged.*

No other code path touches the taxonomy.

## Risks

- **Stale labels file.** If the h5ad is updated but the blessing step
  isn't re-run, downstream silently uses stale labels. Mitigation:
  `taxonomy.load_labels()` checks `MANIFEST.source_h5ad_sha256`
  against the on-disk h5ad and refuses to load on mismatch (with a
  clear "re-run alz/celltype_blessing.py" message).

- **Path B gate change.** Real behavior change, but it's intentional
  and surfaced explicitly in the open question. Measure before
  committing.

- **Hard-coded literal class strings.** Bare forms (`"IT-ET Glut"`)
  are easy to miss in `grep`. The audit needs both prefixed and bare
  forms; missed ones will fail loudly the next time the taxonomy
  changes, since `taxonomy.classes` is a closed vocabulary.

- **External-CSV format drift.** If Allen ships a new
  `wmb_subclass_to_class.csv` with different column names, the
  blessing script needs to localize the read. That's strictly easier
  than today, where the loader lives in `config.py` and gets reached
  for in surprising places.
