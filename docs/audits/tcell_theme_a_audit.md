## A1 — Specificity / enrichment terminology

### Current state

**"Specificity" in the viewer** (`kinase_audit.js` ATTR_VERDICT_COLS, lines 606–619) means two things that are not clearly distinguished:

- **Within-cohort specificity** (`tcell_tier`, `tcell_specificity`): transcript share of this kinase in each ProjecTILs T-state from our own scRNA (`alz/cross_reference/tcell_within_cohort.py`). Computed as `mean_in_state / Σ_states mean_in_state`, binned at 1×/2×/5×/10× of 1/N_states. This is the Song S2 analog, pooled across days. Stored in `outputs/reports/kinase_attribution_tcells/donor1/tcell_specificity.csv` (columns: `gene, state, tcell_specificity, tcell_mean_log2_expression, tcell_tier`).

- **NSCLC external reference tier** (`nsclc_tier`): T_NK-compartment coarse share, shown as a fold-over-1/7-uniform badge. Intended to cross-check T-lineage expression in an independent dataset.

**The NSCLC lineage strip** (`_renderNSCLCLineageStrip`, `kinase_audit.js:916`) is silently broken: it reads `r.specificity_score` (line 600, 931) from `nsclc_kinase_expression.csv`, but that column does not exist on disk. The CSV has `concentration`, `concentration_of_total`, `concentration_tier` instead. The current script (`alz/reference/nsclc_expression.py:377–382`) outputs `specificity_score`, but the CSV was generated by an uncommitted intermediate version. The `.pyc` in `__pycache__` confirms the compiled version that ran had different output columns. Every call to `_nsclcGroupShares()` returns 0 for every group → all tier badges render as empty.

**"Enrichment" is not surfaced** anywhere in the viewer. Per A1's definition (ProjecTILs-state concentration from scRNA), the candidate data sources are:
- Our scRNA: `tcell_specificity` (concentration share per state) — already computed, labeled "Share" in the verdict table, not "enrichment."
- NSCLC native T-states: `nsclc_kinase_expression.csv` has 14 ProjecTILs states (CD4.*, CD8.*, CD4.Treg) at native resolution with `fraction_cells_expressing` and `concentration` per state — but the viewer collapses all T-states into a single T_NK bucket.

**"How many of 7 NSCLC cell types express at ≥10% detection"**: The `binary_expressed` column in `nsclc_kinase_expression.csv` already encodes `mean_log2 > 1 AND fraction_cells_expressing > 0.10` (line 354 of `nsclc_expression.py`). But "how many of 7 coarse groups" requires the coarse group detection count — this is `n_detected_coarse` in `nsclc_kinase_specificity.csv` (NOT currently loaded into the viewer). The expression CSV has `binary_expressed` at native T-state level; the specificity CSV has `group_detected` at coarse level, but only the expression CSV is registered.

**Sort/breakdown by CD4, CD8, Treg**: The NSCLC expression CSV has 14 native ProjecTILs T-states with `spec_group = T_NK`. The viewer collapses them all into one T_NK chip. No CD4 vs CD8 vs Treg split exists in the viewer UI or payload.

### Gap

| Item | Gap |
|------|-----|
| NSCLC CSV stale | `nsclc_kinase_expression.csv` has `concentration` not `specificity_score`; lineage strip shows all 0s. Must regenerate with current script. |
| n_detected_coarse not in viewer | `nsclc_kinase_specificity.csv` has `n_detected_coarse` (# of 7 coarse groups detected) but that file is never loaded; not surfaced in UI. |
| "Enrichment" label absent | ProjecTILs-state concentration is computed (as `tcell_specificity`) but never called "enrichment" in the viewer; A1 wants a distinct enrichment concept. |
| NSCLC native T-state breakdown absent | 14 T-states folded into T_NK; no CD4 / CD8 / Treg breakdown in the NSCLC lineage strip. |
| CD4/CD8/Treg sort absent | No filter or sort option by T-cell sublineage in any panel. |

### Files to change

- `alz/reference/nsclc_expression.py` — regenerate the CSV with current code; or reconcile column name (`specificity_score` → `concentration`) in both script and JS.
- `alz/tcell_viewer/slices_audit.py:296–306` — register `nsclc_kinase_specificity.csv` as a second audit table (provides `n_detected_coarse`, `group_detected`, `group_fraction`).

## A2 — Attribution: "vs bulk" → NES deconvoluted

### Current state

In the attribution verdict table (`kinase_audit.js:614`):
```js
{key:"tcell_concordance", label:"vs Bulk", type:"num", group:"attr", ...}
```
`tcell_concordance = sign(bulk_NES) × tcell_lfc` — a signed product of the bulk MEA direction and the transcript's log2FC vs d2. It is not a deconvoluted NES. It is directionally uninformative (OR≈1 per the caveat in `alz/tcell_viewer/common.py:27–31`) and is shown as a label only.

The "NES deconvoluted" value would come from the **projected-state MEA**: `alz/cohorts/tcells/state_mea.py` runs MEA on deconvoluted per-state substrate matrices (from `ps_deconvoluted.csv` and `py_deconvoluted.csv`) to produce a per-state NES × contrast table. The payload loader `_load_projected_state_mea_payload()` (`alz/tcell_viewer/slices_kinase.py:186`) already exists and reads from `outputs/reports/kinase_attribution_tcells/donor1/state_mea/`. However, **that directory does not exist** — the projected-state MEA has never been run for this cohort.

The bar-chart "decomp NES" panel in the kinase audit drawer (`kinase_audit.js:380–437`) reads `PAYLOAD.decomposition_index` (`kinase_explorer.js:184`). The T-cell payload does NOT build `decomposition_index` — it's an AD-cohort artifact. So the decomp NES chart is always empty for T-cell.

### Gap

- `outputs/reports/kinase_attribution_tcells/donor1/state_mea/` does not exist — `alz/cohorts/tcells/state_mea.py` has never been run.
- Even when state_mea runs, its output is currently loaded into `payload["projected_state_mea"]`, not wired into `decomposition_index` (which is what the decomp NES chart reads from).
- The "vs Bulk" label in the verdict table is technically correct for what the column contains (concordance product), but A2 wants it replaced or supplemented with the actual per-state NES from state_mea.

### Files to change

- Run `alz/cohorts/tcells/state_mea.py` for donor1 to produce `outputs/reports/kinase_attribution_tcells/donor1/state_mea/mea_projected_state.csv`.
- `alz/build_tcell_viewer.py` or `alz/tcell_viewer/slices_kinase.py` — wire `projected_state_mea` rows into a `decomposition_index`-compatible structure so the existing bar chart renders.
- `alz/tcell_viewer/template/js/tabs/kinase_audit.js:614–615` — rename "vs Bulk" label to "NES decomp" (or add a separate column) once the data is available. Alternatively rename the column to show the state NES directly.

## A5 — Monotonic trend export script

### Current state (exists)

**Script:** `alz/cohorts/tcells/monotonic_export.py`

**Invocation:** `pixi run python -m alz.cohorts.tcells.monotonic_export [options]`

**What it does:**
- **Kinase side** (donor1 only; donor2 skipped — no IMAC): reads `kinase_timepoint_nes.csv` and `kinase_timepoint_nes_pY.csv`, prepends an implicit NES=0 at d2, tests for monotone increase/decrease across timepoints d2→d13→d15→d17→d19→d20. Outputs `monotonic_kinases.csv` (columns: `donor, track, kinase, direction, n_timepoints, value_d2, value_d{N}…, range, slope_ols`).
- **Substrate side** (all available: donor1 ST+pY, donor2 pY): reads `raw_phospho_normalized{,_pY}.csv` or `stoichiometry_matrix{,_pY}.csv` depending on `--track-kind`. Applies weak/strict monotonicity test with `--min-obs` NaN filter. Outputs `monotonic_substrates.csv`.

**Default output directory:** `outputs/reports/kinase_attribution_tcells/monotonic/`

**Flags:** `--strict` (strict inequalities), `--min-obs INT` (default 3), `--include-constant`, `--out-dir PATH`, `--verify` (runs assertions after writing).

**Status:** Script exists and is complete. No evidence it has been run (no `monotonic/` directory exists under `outputs/reports/kinase_attribution_tcells/`). Not surfaced in the viewer.
